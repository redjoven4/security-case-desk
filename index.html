      JSON format guide

      The official format is a JSON array of reports, [ { … }, { … } ], with one or more reports. Every report needs these four fields, each a non-empty piece of text:

      FieldRequiredWhat it holds
      report_idYesThe report's unique ID, for example CASE-TEST-101 (max 80 characters)
      titleYesShort summary shown in the inbox (max 200)
      messageYesThe message being investigated (max 5,000)
      contextYesWhat is known about the situation (max 2,000)

      Optional, and shown on the case when present: channel, sender (the name as displayed; it doesn't prove who sent it), reportedBy and receivedAt (a date such as 2026-10-22T18:30:00+08:00). Any other fields are kept as additional fields and never cause a rejection. Older files that use id instead of report_id, or background instead of context, are still accepted. A single report on its own, or { "reports": [ … ] }, also works.

      The whole file is checked first: if any report is missing a required field, or has one that is empty, nothing is imported and your existing cases stay as they are. A report whose ID is already on the desk (or appears twice in the file) is skipped, never overwritten. Limits: 5 MB and 2,000 reports per file. Use placeholders such as [link omitted] instead of real links, codes or personal details.
