INVESTIGATION 1 - CASE-002 "Gaming prize asking for sign-in code"
-----------------------------------------------------------------------
Original report
  Message: A gaming account sends: "Congratulations, you won a prize! Reply
           with the sign-in verification code you just received to claim it."
  Context: No actual sign-in code or working link is provided. The sender and
           prize have not been independently verified.

Suggested evidence (note -> source)
  1. The message asks the recipient to reply with a sign-in verification code.
     -> Source: Original report (starter_cases.json)
  2. The game's official help page says support staff never ask players to
     disclose one-time sign-in codes. The prize sender has not been verified.
     -> Source: recreated follow-up card

Possible interpretations
  - Account takeover attempt: whoever has the code can sign in as the player.
  - A genuine prize is unlikely to need a sign-in code; no legitimate reason
    is given in the report.
  - Uncertain: who the sender is. The code request stays risky either way.

Recorded outcome: Concern supported (case closed)
  Reason (suggested): The message asks for a one-time sign-in code, which the
  game's help page says staff never request.
Suggested safe next step: Do not send any code. If a prize is claimed, check
  it only through the game's official app or website, typed in directly.

INVESTIGATION 2 - CASE-003 "Tournament fee"
-----------------------------------------------------------------------
Original report
  Message: A familiar-looking tournament message says: "Please pay the
           registration fee before tonight to keep your place."
  Context: The supplied context does not confirm whether the fee is real or
           whether the sender is an authorised organiser.

Suggested evidence (note -> source)
  1. The message asks for payment by tonight; the context does not confirm the
     fee or the sender.  -> Source: Original report (starter_cases.json)
  2. A separately obtained organiser notice lists a registration fee, but gives
     a different deadline than the message.  -> Source: recreated follow-up card

Possible interpretations
  - Genuine fee with a mistaken or outdated deadline in the message.
  - A copycat message using a real event to push a rushed payment.
  - Uncertain: whether the sender is an authorised organiser, and which
    payment method is real.

Recorded outcome: Unresolved (case left Investigating, not closed)
  Reason (suggested): A fee may be real, but the message's deadline conflicts
  with the organiser notice and the sender is not confirmed.
Suggested safe next step: Pay only via the method and deadline on the
  organiser's own notice, after confirming with the organiser through a
  contact you already know.

     Next step: Check the club noticeboard before telling others.

   Reason: The noticeboard, the normal source for room changes, contradicts
     the chat message and no organiser has confirmed the change.
   Next step: Do not pass the room change on; ask the club organiser directly
